# Workflow — Жёсткий чеклист перед стартом

## 📡 MCP-интеграция с Allure TestOps

**Перед написанием тестов используй MCP-инструменты вместо поиска по файлам:**

- `testops_find_testcases` — искать тест-кейсы по проекту
- `testops_find_testresults` — искать прогоны (раны)
- Подключён к: `https://rallyup.testops.cloud`

**Как использовать:**
```
# Найти тест-кейс по ID
testops_find_testcases(query="72600")

# Найти прогоны по проекту
testops_find_testresults(projectId="ID_ПРОЕКТА")
```

**❌ ЗАПРЕЩЕНО:**
- ❌ Искать тест-кейсы через grep по файлам
- ❌ Придумывать TC-номера — бери из TestOps через MCP
- ❌ Писать номер кейса в названии теста (`@TC-…`) — только `await allure.allureId('<test_case_id>')` первой строкой теста (AGENTS.md §6)
- ❌ Использовать allure_id 91XXX — только test_case_id

## 🚨 КРИТИЧЕСКОЕ ПРАВИЛО — Ожидание загрузки данных

**ПЕРЕД НАПИСАНИЕМ ЛЮБОГО ТЕСТА, КОТОРЫЙ РАБОТАЕТ СО СПИСКАМИ ЗАПИСЕЙ — ПРОЧИТАЙ ПУНКТ 17 В test-reliability.md**

### Правила:
1. **После `goto()`** → ждать `heading` или `newButton` (признак загрузки данных)
2. **После `fill(searchInput)`** → искать через `getByRole('row', { name: email })`, не через `getRow(email)`
3. **После create/update/delete** → ждать подтверждения → возврат на список → ждать `heading`
4. **Длинные email** → могут обрезаться в grid, использовать поиск для точного совпадения

### BAD:
```ts
await coachPage.goto();
await expect(coachPage.getCoachRow(COACH_EMAIL)).toBeVisible();  // FAIL: данные не загрузились
```

### GOOD:
```ts
await coachPage.goto();
await expect(coachPage.heading).toBeVisible({ timeout: TIMEOUTS.medium });  // Данные загрузились
await coachPage.searchInput.fill(COACH_EMAIL);
await expect(coachPage.getRowByEmail(COACH_EMAIL)).toBeVisible({ timeout: TIMEOUTS.long });
```
