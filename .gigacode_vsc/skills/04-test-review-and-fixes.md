# Скилл 04: ревью и правки (обязательный последний шаг)

**Вход:** тест, проходящий локально (03). **Выход:** отчёт в чат, правки, повторный PASS, статус кейса в `PLAN.md`.

**Холодное ревью:** оценивать только текущий код, как чужой — без истории правок и отброшенных вариантов.

## Шаги
1. **Ревью → отчёт в чат.** Открыть спек и используемые PO, пройти `test-review-checklist.md`. Каждое нарушение — строка отчёта; в код комментарии не добавлять.
2. **Смысл теста** (главное — ложный PASS):
   - название ↔ ассерты: проверяется то, что обещано в `test('…')`;
   - шаги кейса из TestOps (MCP) ↔ код: каждый `exp` проверен; непокрытое — в `test.skip` с TODO (AGENTS §6);
   - каждый ассерт падает, если проверяемого нет (быстро: временно сломать ожидание и прогнать);
   - нет «мёртвых» шагов (ожидание без последующего действия, ассерт, который проходит всегда).
3. **Правки.** Нарушения AGENTS и чек-листа — исправить. Изменить, что проверяет тест (ассерты, шаги, данные), или правка общего файла — только с согласия пользователя (AGENTS §2).
4. **Повторный прогон** локально (`npm run test:<роль> -- --grep "…"`, `typecheck`, `lint`).
5. **Итог:** отчёт (формат — в конце чек-листа) + что исправлено + PASS/FAIL + что тест создаёт на стенде. Обновить статус кейса в `PLAN.md`.

Сценарий завершён. `05-test-harvester.md` — по желанию пользователя.
