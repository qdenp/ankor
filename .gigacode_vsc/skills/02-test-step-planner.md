# Скилл: Планировщик Шагов Теста

## Назначение
После утверждения сценария — детализировать шаги, определить точные локаторы, методы PO, пользователей и данные.

## Когда использовать
После того как Анализатор Тестовых Сценариев составил план и пользователь его утвердил.

## Порядок выполнения

### Шаг 1: Анализ Page Objects
- Прочитать соответствующие page object для функционала
- Определить существующие методы, которые можно использовать
- Определить существующие локаторы, которые можно применить
- Проверить, нужно ли создавать новые методы PO

**Файлы PO в проекте (tests/pages/):**
```
athlete-page.ts      — Athletes CRUD, search, table rows
coach-page.ts        — Coaches CRUD
parent-page.ts       — Parents CRUD
plan-page.ts         — Practice Plans CRUD, tabs, drills
organization-page.ts — Organizations CRUD
team-page.ts         — Teams CRUD
sign-in-page.ts      — Login flow
sign-up-page.ts      — Registration flow
home-page.ts         — Home/dashboard
base-page.ts         — Base class, shared methods (logout, navigation, wrappers)
```

### Шаг 2: Соотнесение UI элементов с селекторами
Для каждого шага в утверждённом плане:
- Найти соответствующий элемент в PO
- Если элемент есть в PO → использовать его
- Если элемент есть на странице, но не в PO → предложить добавить в PO
- Если элемента нигде нет → предложить новый локатор PO + метод

### Шаг 3: Определение требований к пользователям
- Проверить, какие пользователи из `tests/config.ts` нужны (CREDENTIALS object)
- Проверить уникальность email (каждый email используется только один раз)
- Проверить, нужно ли создавать новых тестовых пользователей в `00-create-users.spec.ts`
- Проверить, соответствуют ли роли пользователей требованиям теста

### Шаг 4: Создание детального плана реализации
```
## План реализации: [Название теста]

### Page Objects
**Существующие:**
- `PageObject.method()` — [что делает, ссылка на строку]
- `PageObject.locator` — [что выбирает]

**Создаваемые:**
- `PageObject.newLocator = page.getByRole(...)` — [назначение]
- `PageObject.newMethod()` — [назначение, шаги внутри]

### Тестовые данные
**Существующие пользователи:**
- [роль] — [email] — [можно использовать, потому что...]

**Необходимые новые пользователи:**
- [роль] — [шаблон email] — [зачем нужен]

### Пошаговая реализация
1. Создать локатор PO: `readonly xxx = page.getByRole(...)`
2. Создать метод PO (если нужно): `async xxx(): Promise<void>`
3. В тесте: `await pageObject.goto()`
4. В тесте: `await pageObject.xxx()`
5. В тесте: `await expect(po.property).toHaveText('zzz')`

### Соотнесение ассертов
| Шаг | Ассерт | Источник локатора | PO метод/свойство |
|-----|--------|-------------------|-------------------|
| Проверить заголовок | `expect(po.heading).toBeVisible()` | PO | heading |
| Проверить количество | `expect(po.rows).toHaveCount(N)` | PO | athleteRows / getAthleteRow() |
| Проверить URL | `expect(page).toHaveURL(/route/)` | Встроенный | — |
| Проверить текст | `expect(po.cell).toHaveText('value')` | PO | getAthleteRow(email) |
```

### Шаг 5: Проверка по существующим паттернам
- Сравнить с похожими тестами в той же папке ролей (`tests/specs/owner/`, `coach/`, `parent/`, `athlete/`)
- Убедиться в согласованности соглашений о наименовании
- Проверить корректность использования фикстур (`loginAs`, `logout`)
- Проверить, настроен ли serial mode при необходимости

### Шаг 6: Предоставление на утверждение
Показать детальный план реализации и запросить подтверждение.

## Правила
- ВСЕГДА читать реальные файлы PO перед предложением локаторов
- ВСЕГДА проверять, существует ли уже метод/локатор
- ВСЕГДА проверять, что emailы пользователей не использовались ранее
- ВСЕГДА следовать дисциплине PO (локаторы в конструкторе, методы для действий)
- ВСЕГДА использовать `getByRole`, `getByPlaceholder`, `data-test` атрибуты когда возможно
- Если нужно создать метод PO — показать точный код для добавления
- Учитывать надёжность: использовать несколько стратегий для строк таблиц (цепочка `.or()` / `.filter()`)

## Формат вывода
Представить план реализации с чёткими секциями и спросить:
"Утверждаете ли вы этот план реализации? После этого я напишу код."
