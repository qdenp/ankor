# Скилл 01: анализ сценария

**Вход:** номер кейса TestOps или описание сценария. **Выход:** план, утверждённый пользователем. Кода на этом шаге нет.

## Шаги
1. **Кейс.** Шаги, ожидания и предусловия — из TestOps через MCP (`testops-integration.md`), не по памяти и не из CSV. Определить роль, раздел меню и файл `NN-topic.spec.ts` (AGENTS §6).
2. **Покрытие.** Статус кейса — в `PLAN.md`; есть ли тест — `grep -rn "allureId('<id>')" tests/specs`. Похожие тесты — в `tests/specs/<роль>/` того же раздела. Нашёлся тест, покрывающий кейс частично, — предложить доработать его, а не писать новый.
3. **Данные.** Что тест создаёт на стенде и можно ли это удалить (AGENTS §9). Создавать запись — только если кейс проверяет само создание; иначе взять существующую (`test-data-store`, константы `config.ts`, пользователи ролей из `.env`). Неудаляемые действия (Submit оценки, новые пользователи) — явно отметить в плане.
4. **План** — показать пользователю:
   - кейс (номер, название), роль, файл, PO;
   - предусловия и данные (что создаётся, что переиспользуется);
   - шаги кейса → что проверяет тест на каждом (web-first ассерты через PO);
   - что не покрывается и почему (→ `test.skip` с TODO, AGENTS §6);
   - новые методы/локаторы PO; затронутые общие файлы (нужно одобрение — AGENTS §2).
5. **Утверждение:** «Утверждаете план?» Простой сценарий — вместе с таблицей 02 одним сообщением.
